# AIVideo 現況與優化方向

> 只依目前在跑的產品：`web/` React Studio（:5173）+ `aivideo/api` FastAPI（:8000）+ CLI 產線 + `jobs/` 檔案專案。  
> 日期：2026-10-03。本文件是優化目標與優先順序，不是已實作規格。

---

## 0. 現在這套產品是什麼

AIVideo Studio 是 **長篇中文說書成片工廠**：

主題／口白 → 6～8 段故事大綱 → 逐句旁白 → 語意切成數十個鏡頭 → Gemini 16:9 靜圖 → OmniVoice 配音 → FFmpeg Ken Burns + 字幕 → 1080p →（可選）YouTube。

實際規模以現有專案為準：一份約 8 幕大綱，會切成 **40+ 鏡頭**（例如百事可樂 job 43 場）。操作者面對的是「長片導演台」，不是 6 張圖的短片工具。

硬體與產線邊界維持現況：雙容器（pipeline CPU / ComfyUI GPU）、Gemini 出圖、OmniVoice TTS、產物落在 `jobs/{date}_{slug}/`。

---

## 1. 優化北極星

創作者在任一頁都能立刻回答兩件事：

1. **現在該按哪一顆。**
2. **這一場的圖／聲／口白對不對；不對時怎麼只修這一場。**

達標定義：從空白主題到可審的 1080p，主路徑少確認、少誤按；單場重抽能對比歷史 takes、鎖定滿意結果、從成片某一秒跳回該鏡頭。

YouTube、PiP 考據、風格畫廊、模型切換都是高價值附加，排在主路徑之後。

## 2. 現況能力（已能做的）

| 層 | 現況 |
|---|---|
| 介面 | 左欄六頁：總覽、腳本、分鏡、成片、素材、設定。分鏡有網格 + 右欄 Inspector。SSE 顯示批次進度。 |
| 腳本 | 口吻仿寫、規劃大綱、擴寫、視覺錨點分析、指定故事要求、建案切鏡。口白生成已只吃語氣「核心口白」樣本，並過濾大綱導演註記。 |
| 分鏡 | 批次出圖／配音／考據／合成；單場重抽圖、重錄、PiP、改 prompt／口白。指揮列可清空圖、聲、全部素材。 |
| 成片 | 播放 `film.mp4`、下載 MP4／SRT／ASS、YouTube 發布彈窗（標題優化、縮圖、隱私、字幕）。 |
| 素材 | 口吻 Markdown、發音人、27 套畫家風預覽與編輯。 |
| 產線 | `images` / `tts` / `srt` / `compose` / `preview` / `youtube` 可用。磁碟上 `takes/` 會累加。 |
| 資產實盤 | 口吻 2 套（`michelin_curious`、`warm_narrative`）；發音人 `tw_female01`、`hk_male01`。 |

這些能力已經構成完整工廠。優化不是再加一條產線，而是讓現有工廠 **可導、可修、資料誠實**。

## 3. 主路徑目標

收成一條清楚的導演流程：

```
主題 → 口白（人審）→ 建案切鏡
  →（可選）定裝
  → 出未完成圖 → 聽未完成聲 → 合成
  → 成片時間軸點一場 → 精修 → 再合成
  →（可選）發布 YouTube
```

進階全部進 `⋯` 或設定：換畫風、強制全覆蓋、PiP、模型、清空、刪專案。

## 4. 方向一：腳本頁變成「寫稿台」，不要當控制室

現在腳本頁同時承擔：選口吻、選發音人、選風格畫廊、指定 Prompt、6 幕大綱、視覺錨點、字數、模型、貼口白、AI 生成、建立專案。第一屏決策過載。

預設還塞著羅曼望遠鏡示範稿，新建時很容易把範例建成 job。

選了已有專案會載入口白與設定，按「建立專案」仍會 **再造一個新日期資料夾**（同一主題出現 `20261001_…` 與 `20261003_…`）。API 已有 `PATCH script`，畫面上沒有「寫回此專案」的一等動作。

### 目標

- 預設空白草稿。
- 兩條入口分開：**貼上已有口白**、**從主題生成**。
- 第一屏只留主題、口白、字數、口吻。風格改點「更換」開 modal。故事要求／大綱／錨點預設收合。
- 明確兩種模式：**新專案草稿** vs **編輯此專案**。後者儲存後再問是否重切分鏡。
- 「指定 Prompt」改名為「故事要求／必寫看點」，避免被當成出圖 prompt。
- 建案可編輯 ASCII 資料夾名；建案期間要有進度（一串串行 LLM：切鏡 + 英文 prompt + PiP query）。

## 5. 方向二：單場精修閉環（這是目前最大缺口）

磁碟上 takes 已在累加（單場可到數十個 wav/png），但產品用不上：

- CLI `lock` / `unlock` / `select` / `regen` / `parse` / `run` 仍是 stub。
- React 沒有 take 瀏覽、沒有選定 current、沒有 lock 徽章。
- 「重抽這張圖」直接覆蓋 current；上一張比較好只能去資料夾挖。
- `scene.yaml` 的 `locks` 永遠 `false`。
- 成片頁只有播放器 + 下載 + YouTube，**沒有時間軸**。要修某一秒，只能憑記憶回網格找「第 N 幕」。43 場時不可用。

### 目標

- Inspector 列出本場歷史圖／聲，點一下設為 current。
- lock 後批次與重抽跳過該槽。
- 成片頁時間軸：每場一塊，點擊跳轉分鏡並打開該場。
- 網格標題用劇情短句，並依大綱幕次分組。`title: 第 17 幕`、`id: 001_scene_1` 對導演沒有資訊。
- 大綱幕次（Act）與鏡頭（Shot）分成兩層，文案分開：「故事大綱 6～8 段」與「鏡頭約 N 張」。

精修閉環的優先級高於再加發布功能。

## 6. 方向三：產線可控、主按鈕跟缺件走

頂列主按鈕在分鏡頁是「一鍵生成 (圖+聲+考據)」，缺圖或缺聲時一律跑 `all`（含 PiP）。不想考據的歷史／虛構片沒有「只出圖+配音」的主路徑。指揮列另有出圖／考據／配音／合成／清空／定裝／發音人／片長／燒字幕，一列塞爆。

批次進行中只有停止。`PipelineRunner` 有 pause，API 寫死 `pause_between_stages=False`，React 沒有暫停。長 job（43 場出圖 + TTS + 配額冷卻）只能停或乾等。

進行中每 1.5 秒整表 `loadScenes` + `loadJobs`，43 場會打爆 API、網格閃爍。Inspector 重抽另用 2 秒輪詢，與 SSE 脫鉤。

### 目標

- 頂列主按鈕只跟缺件：缺腳本 → 生成腳本；缺圖 → 生成未完成畫面；圖齊缺聲 → 生成配音；圖聲齊 → 合成 1080p；已有成片 → 預覽成片；進行中 → 進度 + 暫停。
- PiP 是 job 級開關，預設關；一鍵 all 不偷偷跑考據。
- 指揮列只留幽靈「出圖／配音／合成」。定裝、考據、清空、強制覆蓋進 `⋯`。
- 暫停／續跑接到 UI。
- SSE 帶 scene id，只補那一張卡。管線狀態落盤 `jobs/<id>/run.json`，reload 不丟進度。

## 7. 方向四：資料誠實（畫面與檔案要說真話）

### 7.1 預設對不上磁碟

程式、schema、UI 預設與既有 job 的 `voice_id` 已對齊磁碟 `tw_female01` / `hk_male01`。display_name 與資料夾 id 仍可再分開（素材頁）。風格 job 可能寫 `european_fairytale`，`style_prefix` 卻是另一套，屬 P2。

### 7.2 路徑含中文、場景無名

建案用 `re.sub(r"[^\w\s-]", "", topic)`，Python 3 的 `\w` 含中文，得到 `20261003_百事可樂的蘇聯海軍`。Windows + Docker bind mount 容易痛。場景全叫 `scene_N`，檔案總管無法辨識。

目標：資料夾 ASCII slug（可編輯）；場景 id 用拼音或口白短語；中文只寫進 yaml 的 `title`。

### 7.3 口白檔與字幕被產線污染

- 建案把定裝／環境錨點寫進 `script.md` 的引用塊，之後重切鏡可能混入口白。
- `apply_pronunciation_mapping` 在切鏡時就把「企→氣」寫進 `narration`，字幕會出現「氣業」。TTS 再 map 一次即可。
- OmniVoice 情緒標籤 `[surprise-wa]` 仍在旁白裡；SRT／畫面應剝標籤，TTS 保留。

目標：`script.md` / `narration` / SRT 永遠正確漢字、純口白；諧音與情緒標籤只在送 TTS 前處理。

### 7.4 `job.yaml` 過肥

單檔同時塞整份 outline、超長 `visual_anchors.subject`、characters、YouTube metadata。已有 `outline.md`、`script.md`、`characters/*.png`。

目標：

```
job.yaml          # 短設定：title, voice_id, style, frame, subtitle, kenburns, use_pip
outline.md        # 大綱唯一來源
script.md         # 口白唯一來源
anchors.yaml      # 角色 / 環境 / 是否用參考圖
compose/youtube.json
```

### 7.5 安全與靜態檔

`/media` 掛整個倉庫，等於原始碼與 `assets/credentials` 可經 8000 讀出。應只掛 `jobs/`、風格預覽、語音試聽。

頂列 `⋯` 下載 SRT 指到 `/compose/film.srt`，真實檔是 `timeline.srt`（成片頁路徑正確）。這是功能 bug。

`assets/fonts/` 空，job 卻寫 `NotoSansTC-Regular.otf`。要嘛放字型，要嘛 yaml 指到容器真實路徑。

takes 只加不收；需要 `gc --keep N` 與 UI 顯示本場張數／磁碟占用。

## 8. 方向五：畫面紀律（讓「該按哪顆」成立）

`doc/ui-redesign.md` 的骨架仍然適用現況，當驗收標準即可：左欄只切頁、頂列一顆實心主按鈕、右欄按需開啟。

現況偏離：

| 位置 | 現況 | 目標 |
|---|---|---|
| 左欄底部 | 文本模型 + 生圖模型 | 只留導航與收合；模型進設定 |
| 左欄 | 專案下拉 + 刷新 + 縮影 | 專案選擇放頂列一處 |
| 頂列 | 只在分鏡頁常駐 | 各頁都有對應主 CTA（腳本頁＝生成腳本／建案） |
| 成片 | YouTube 紅按鈕最大 | 播放器是主角；發布與下載進次要 |
| Inspector | 發音人下拉 | 發音人是整部片設定，移出單場 |
| 設定 | 展示 localhost:8000、/media | 接 Gemini／Comfy 連線燈與檢測；開發資訊摺疊 |
| 總覽 | 點卡片只 select、不換頁 | 點縮圖進分鏡；可留刪除 |

文案用短標籤：`生成腳本`、`出圖`、`配音`、`合成`、`匯出`。系統燈要兩顆（Gemini、Comfy），現在只有 API 8000。

危險操作分級：清空圖／聲／全部／刪專案已有 `confirm`，強制全覆蓋要獨立入口，避免「先清空再生成」兩步都危險。

## 9. 方向六：啟動入口與死碼

創作者日常入口是 **API 8000 + Vite 5173**。Streamlit / 8501 / `webui.py` 已移除；compose 轉發 8000 與 5173。

dev-kit 的 AIVideo tasks 仍以 Streamlit 為清單最上項，沒有「啟動 Studio」。CLI 批次 task 預設路徑還是示範 job，且 `compose run --rm` 每次新容器，會丢掉行程內的管線狀態。

### 目標

- 產品介面只留 React。拿掉 Streamlit 依賴、8501、`webui.py`。
- tasks：啟動 API、啟動 Vite（或一鍵 Studio）、保留 ComfyUI；CLI 日常以 Studio 為主。
- 容器內產線用 `docker compose exec pipeline`，對到同一個跑著 uvicorn 的行程。
- README 寫 Studio 啟動步驟。`ui.md` 改寫成現行介面。`規劃.md` 只留硬體／容器／產線不變原則。

文件選定真相來源：操作手冊＝改寫後的 `ui.md`；本文件＝優化 backlog；規劃＝不變的產線憲法。

## 10. 生成品質（跟導演能看見的東西綁在一起）

- 切鏡標題用該場第一句口白或大綱短句，網格才看得出「這張是廚房辯論」。
- 確認 `style_prefix` 不要與 `image_prompt` 開頭的中文風格句疊加兩次。
- 換風格要有向導：同步 prompt →（可選）重產定裝圖 → 再出未完成圖。現在三步分開，容易出現「童話 job + chibi prefix + 寫實人物描述」。
- 大綱／腳本的 Google Search 在 UI 要有關閉開關（費用、速度、幻覺）。
- 前端模型清單與後端 fallback 同源；選了不存在的模型要在設定頁就失敗，不要執行時默默 fallback。

口白品質已有的方向維持：腳本只吃核心口白樣本；sanitize 繼續擋幕次標題與「讓觀眾／帶給觀眾」導演句。大綱生成仍可吃完整 tone（含結構公式）。

- 不要在左欄再加 YouTube／模型／進度。
- 不要推翻雙容器、Gemini 出圖、OmniVoice TTS、檔案系統 takes。
- 不要把 job 改成資料庫。缺的是命名、UI 選定、與主路徑收斂。
