# AIVideo 規劃：字幕、語音、圖片合成影片

本文件是這個專案的作法依據。目標是在本機用 **Docker Desktop + Dev Container + VS Code + ComfyUI**，把中文腳本做成「旁白語音 + 畫面 + 字幕」的影片，並且**單段不滿意時只重產那一段**。

第一版產品形態：**16:9 靜態圖 + Ken Burns 推鏡 + 台灣華語旁白 + SRT 字幕**。畫面由 **Google Gemini 影像模型**（Nano Banana 系）在雲端產生；本機 GPU 只跑 OmniVoice TTS。不做對口型、不做長鏡頭連貫角色、不做 AnimateDiff / 圖生影片。

## 1. 硬體現實（必須先接受）

| 項目 | 規格 | 對本專案的含義 |
|------|------|----------------|
| CPU | Ryzen 7 3800X 8 核 | 腳本解析、FFmpeg、編排都夠用 |
| RAM | 64 GB | 最大優勢。模型可卸到 RAM，WSL 記憶體可給 32–48 GB |
| GPU | **RTX 2060 6 GB**（Turing, SM 7.5） | **只留給 OmniVoice TTS**。出圖改走 Google API，不再跟 TTS 搶顯存 |
| 233 GB NVMe | WDS250G3X0C | 作業系統用。不要堆模型 |
| 932 GB SSD | CT1000MX500SSD1 | **模型、Docker 資料、WSL 磁碟、輸出**放這裡 |
| 466 GB SSD | CT500P2SSD8 | 專案程式碼、工作檔備援 |
| 466 GB HDD | ST3500413AS | 只放封存。不要放 checkpoint |

6 GB 可用顯存實際大約 5.2 GB。出圖改走雲端之後，這張卡只需要扛 TTS：

- ComfyUI 啟動參數：`--lowvram --preview-method none`；**不要開 SageAttention**（需要 SM80+，2060 沒有）。
- Turing **沒有原生 BF16**。權重用 `OmniVoice-bf16`，推論 dtype 用 **`fp16`**。
- TTS 批次結束立刻卸載模型。不要在同一時間載 Whisper。
- 本機 SD 1.5 / SDXL / Flux **不當第一版出圖主力**（當 Google API 掛掉時的備援即可）。
- 成片交付 **1920×1080（16:9）**。Gemini 直接出 16:9（草稿 1K、定稿 2K），FFmpeg 只負責推鏡、字幕、編碼。

若之後換 12 GB 以上顯卡，目錄與 CLI 不用改，只換模型表或把出圖改回本機。

## 2. 架構：兩個容器，不要把 ComfyUI 塞進 Dev Container

```
Windows
 └─ Docker Desktop（WSL2 + GPU）
      ├─ pipeline（VS Code Dev Container 連這裡）
      │     腳本解析、場景表、Gemini 出圖、TTS 編排、SRT、FFmpeg、重產 CLI
      │     環境變數 GEMINI_API_KEY（不進 git）
      └─ comfyui（獨立 GPU 服務，埠 8188）
            OmniVoice TTS（可選：畫布上試 Gemini 節點）
            模型與 custom_nodes 用 Linux 檔案系統上的 volume
```

**為什麼拆開**

- 裝 custom node、改模型會常重啟 ComfyUI；不該連 VS Code 開發環境一起重來。
- 模型 20 GB 以上，不該跟 git 工作區綁在一起。
- 編排用 CPU + FFmpeg；GPU 只留給 TTS。出圖走 Google，不佔 2060。
- 重產某一張圖時，pipeline 直打 Gemini API（或可選打 ComfyUI 裡的 Gemini 節點），不必重跑整張巨型 workflow。

VS Code 只 attach 到 `pipeline`。瀏覽器開 `http://127.0.0.1:8188` 調試 ComfyUI。程式碼透過 ComfyUI `/prompt` + websocket 排隊，不在圖裡硬接整條產線。

### 2.1 磁碟與掛載（Windows 最容易踩的坑）

- **模型絕對不要放在 `C:\` / `E:\` 再 bind mount 進容器。** WSL 讀 NTFS（drvfs）載入數 GB checkpoint 會慢到不能用。
- 模型、Hugging Face cache、ComfyUI output 放 **WSL ext4** 或 Docker named volume，實體位置盡量在 **932 GB MX500**。
- 把 Docker Desktop 的 disk image 移到大 SSD。預設在系統碟很快會滿。
- 程式碼可以留在 `E:\ProjectDir\AIVideo`（若該碟是 466 GB SSD）。
- `.wslconfig` 建議：`memory=40GB`、`swap=16GB`、`processors=8`。

### 2.2 建議映像

- ComfyUI：優先 [mmartial/ComfyUI-Nvidia-Docker](https://github.com/mmartial/ComfyUI-Nvidia-Docker)（WSL2 文件完整，可指定 UID）。選仍支援 **sm_75** 的 CUDA 標籤（例如 12.4 / 12.6），不要盲目追 CUDA 13。
- 映像需含**完整 FFmpeg**（字幕燒錄、音訊合流會用到 filter）。
- pipeline：Python 3.12 精簡映像 + ffmpeg + 本專案套件。不必掛 GPU。

### 2.3 不採用秋叶／繪世整合包當本專案的 ComfyUI

秋叶（秋葉 aaaki）的 ComfyUI 整合包 + 繪世啟動器，在華語圈很常見：解壓、雙擊、中文介面、預裝一堆節點和工作流。**當「自己在 Windows 上玩圖」很好；當這個倉庫的正式後端，不建議。**

| | 秋叶整合包 | 本專案要的 |
|--|-----------|-----------|
| 形態 | Windows 原生、繪世啟動器、嵌入式 Python | Docker Compose 服務，pipeline 用 HTTP API 呼叫 |
| 節點 | 預裝幾十到上百個 | 只裝 OmniVoice（+ 可選 Gemini 手調節點） |
| 重現 | 啟動器一鍵更新，版本容易漂 | 映像 tag、custom node commit 釘死 |
| 2060 / Turing | 新包常預設 CUDA 13、SageAttention、衝 30/40/50 系 | 要 sm_75、`eager`、fp16、lowvram |
| 給 Dev Container | 幾乎接不上 | `COMFY_URL=http://comfyui:8188` |

具體衝突：

- pipeline 在 Linux 容器裡，秋叶 ComfyUI 在 Windows 裡。可以湊 `host.docker.internal:8188`，但 GPU、路徑、權限、重啟都變成兩套世界，lock／takes／API 會一直踩 Windows 路徑。
- 整合包預裝的節點很容易把 PyTorch 降成 CPU 版（OmniVoice 文件已警告 `--no-deps`）。包越大越難查。
- 新版整合包常帶 SageAttention、CUDA 13；2060 是 SM 7.5，Sage 不能用，映像過新可能直接不認卡。
- 預裝工作流／模型會把 233 GB 系統碟或 Docker 盤吃滿；本專案出圖已改 Gemini，不需要那些 checkpoint。

**可以怎麼用秋叶：** 另開一個資料夾當「人手點畫布練手」，跟 `E:\ProjectDir\AIVideo` 分開。不要讓專案 CLI 去打繪世啟動器那個 8188，也不要把整合包解進本倉庫。

若只是不想用 Docker 跑 Comfy、又想要官方維護：看 [Comfy Desktop](https://www.comfy.org/download)，仍比整合包乾淨，但本專案正式路徑仍是 compose 裡的 `comfyui` 服務。

## 3. 流水線順序（字幕跟語音誰先）

不要先寫死 SRT 再硬套語音。語音長度才是時間軸真相。

```
腳本（中文為主）
    ↓ parse
場景表 job.yaml / scenes/*.yaml
    ↓ tts（固定音色 OmniVoice）
每場 speech.wav + 真實時長
    ↓ srt
依真實時長寫 timeline.srt
    ↓ images（Gemini 16:9，一場一張）
每場 image.png
    ↓ compose（FFmpeg，便宜、隨時可重跑）
Ken Burns + 旁白 + 字幕 → film.mp4
```

依賴規則（重產時只碰髒的下游）：

| 你改了什麼 | 必須重跑 | 不必重跑 |
|------------|----------|----------|
| 某場台詞 | 該場語音 → 該場 SRT 片段 → 成片 | 該場圖片（除非你也想換） |
| 某場畫面 prompt / seed | 該場圖片 → 成片 | 語音、SRT |
| 音色檔 | **全部語音** → 全份 SRT → 成片 | 圖片 |
| Ken Burns / 字型 / 解析度 | 只成片 | 語音、圖片 |
| 鎖定（lock）的產物 | 預設跳過 | — |

## 4. 固定音色：OmniVoice

這裡的 **OmniVoice** 是指 [k2-fsa/OmniVoice](https://huggingface.co/k2-fsa/OmniVoice) + ComfyUI 節點 [ComfyUI-OmniVoice-TTS](https://github.com/Saganaki22/ComfyUI-OmniVoice-TTS)，**不是** Qwen2.5-Omni / Qwen3-Omni。後者 3B/7B，6 GB 跑語音不划算。

| 選項 | 磁碟 | 2060 上預估顯存 | 結論 |
|------|------|-----------------|------|
| OmniVoice fp32 | ~4 GB | 8–12 GB | 不跑 |
| **OmniVoice-bf16** + 推論 `fp16` | ~2 GB | 約 4–6 GB，可再開 CPU offload | **主力** |
| 克隆時順便載 Whisper | 額外 0.5–1.5 GB | 會爆 | 參考音訊**預先寫好逐字稿**，不要每次自動 Whisper |
| F5-TTS 中文 | ~1.2 GB | 較輕 | OmniVoice 爆顯存時的備援 |
| Qwen2.5-Omni-3B | 很大 | 裝不下舒適工作流 | 不用 |

節點建議：本專案**逐場呼叫**，才方便單句重產。

- 第一階段（現在）：**OmniVoice Voice Design TTS**
- 第二階段（有台灣華語參考音之後）：改同一份音色檔為 **Voice Clone TTS**，`voice_id` 不變

2060 固定參數：

- `model`: `OmniVoice-bf16`
- `dtype`: `fp16`
- `attention`: `eager`（禁止 `sage_attention`）
- `keep_model_loaded`: TTS 批次內 `true`，批次結束後卸載
- `steps`: 32（不滿意單句可試 16 加速或 64 衝品質）
- 進入克隆後：參考音 3–15 秒、無背景音樂；`ref_text` 手寫，避免載 Whisper

### 4.1 家用音色檔（整部片共用）

音色是專案級資產，不是某一場的設定。建一次、所有 job 引用同一個 id。**先 design、後 clone 時不要換 id**，只改 `mode` 與參考音；已 lock 的語音預設保留，未 lock 的才重產。

建議目錄：

```
assets/voices/narrator_zh_tw/
  voice.yaml
  reference.wav          # 第二階段才放：8–12 秒台灣華語乾淨口白
  reference.txt          # 與 wav 完全對得上的逐字稿
```

第一階段 `voice.yaml`：

```yaml
id: narrator_zh_tw
display_name: 旁白・台灣華語
engine: omnivoice
model: OmniVoice-bf16
mode: design             # 之後改 clone，id 不變
dtype: fp16
attention: eager
steps: 32
speed: 1.0
# OmniVoice 官方 instruct 清單沒有「台灣腔／台灣話」。
# 中英不要混用。性別與年齡可改；改了必須重產未 lock 的全部語音。
voice_instruct: "女，青年，中音调"
seed: 42                 # design 必填且鎖定，跨句才穩
```

第二階段改成克隆時，同一檔改成：

```yaml
id: narrator_zh_tw          # 不要改
mode: clone
voice_instruct: ""          # clone 不再用 design 描述
instruct: ""                # 清單無台灣腔，靠 reference.wav 本身的口音
# seed 對 clone 次要；身份綁在 reference.wav
```

並放入台灣華語 `reference.wav` + `reference.txt`。然後對未 lock 的場跑 `aivideo tts`（或先 `unlock --speech` 再跑）。

**為什麼 design 無法真正指定台灣腔：**  
[ComfyUI-OmniVoice-TTS](https://github.com/Saganaki22/ComfyUI-OmniVoice-TTS) 的 `instruct` / `voice_instruct` 只接受固定清單。中文方言有四川、東北、河南等，**沒有台灣腔**。英文有 `chinese accent`，也不是台灣華語。第一階段能做的是：繁中腳本 + 鎖定 seed 的合成聲，聽起來是「固定的華語旁白」。**要穩定的台灣口音，只能靠克隆一段真正的台灣華語。** 不要把「台灣腔」寫進 instruct，節點會拒絕。

**兩階段作法：**

1. **現在：Voice Design**  
   `voice_instruct: "女，青年，中音调"`（性別可改）+ **seed 寫死**。沒有參考音也能開工。跨句可能微漂，所以 seed 與 instruct 不要動。

2. **之後：克隆（正式音色）**  
   錄或找 8–12 秒台灣華語、單人、無背景。身份綁在 wav，一致性最好。同一 `voice_id`，job 不用改。

整部片只允許一個預設 `voice_id`。以後要第二個角色，再加 `assets/voices/character_xx/`。第一版當單旁白。

**不要做的事：** 每場隨機 seed；在 ComfyUI 裡改節點卻不回寫 `voice.yaml`；design 階段亂填清單外的 instruct。

## 5. 出圖：Google Gemini（16:9），可以進 ComfyUI

**結論：可以。** 但不該指望「Google AI Pro 訂閱」直接等於「ComfyUI 官方 Google 節點的額度」。

### 5.1 兩條進 ComfyUI 的路（計費不同）

| 路徑 | 怎麼用 | 扣誰的錢 | 適不適合本專案 |
|------|--------|----------|----------------|
| **A. ComfyUI 官方 Partner Node**（Nano Banana / Nano Banana Pro / Gemini Image） | ComfyUI 內建，畫布搜尋即可 | **Comfy 帳號點數**，不是 Google AI Pro | 能用，但你的 Pro 用不上。官方文件目前也**不支援填自己的 Google API key** |
| **B. 自備 `GEMINI_API_KEY` 的 custom node** | 例如 [ComfyUI-NanoBanana2](https://github.com/IxMxAMAR/ComfyUI-NanoBanana2)、[ComfyUI-ETNodes](https://github.com/edvardtoth/ComfyUI-ETNodes)、[NakanoSanku/ComfyUI-Gemini](https://github.com/NakanoSanku/ComfyUI-Gemini) | **Google AI Studio / Cloud**，金鑰來自 [aistudio.google.com](https://aistudio.google.com/apikey) | 這才是「用我的 Google AI Pro／Google 帳號」的路 |

Google AI Pro（消費者訂閱）主要是 Gemini App、AI Studio 網頁的用量與模型。**ComfyUI 要打 API**，必須另外建 AI Studio 金鑰。網頁能生圖，不代表這把金鑰一定有影像 API 配額——不少帳號要在對應 Cloud 專案開計費，影像模型才放行。實作 P1 的第一件事：用金鑰對 `gemini-3.1-flash-image` 打一張 16:9，確認 200 再接節點。

### 5.2 本專案預設：pipeline 直連 Gemini，ComfyUI 當可選手調

正式產線**不要**把金鑰寫進 workflow JSON（會進 git、會進 takes 以外的地方）。

```
aivideo images  →  pipeline 用 google-genai SDK
                  讀 GEMINI_API_KEY
                  呼叫 gemini-3.1-flash-image（草稿）或 gemini-3-pro-image（定稿）
                  寫入 takes/ + current image.png
```

ComfyUI 仍可裝 B 類節點，方便在畫布上試 prompt／參考圖。試完把滿意的 prompt 寫回 `scene.yaml`，正式重產走 CLI。

本機 2060 不再跑 SD。Google API 掛掉時，備援才是本機 SD 1.5，不當日常路徑。

### 5.3 模型與畫面規格（已鎖定 16:9）

| 用途 | 模型 | 比例 | 解析度 |
|------|------|------|--------|
| 日常重產、抽 takes | `gemini-3.1-flash-image`（Nano Banana 2） | **16:9** | **1K** |
| 鎖定前的定稿 | `gemini-3-pro-image`（Nano Banana Pro），若金鑰有權限 | 16:9 | **2K**（接近 1920×1080） |
| 成片交付 | FFmpeg 縮放／裁切到 | 16:9 | **1920×1080** |

一場一張靜態圖。運動交給 FFmpeg `zoompan`。

風格一致性與自訂風格：

- job 級 `style_prefix` 拼到每場 prompt 前面（中文主題也可以，Gemini 吃中文比 SD 1.5 穩）。
- **支援自訂圖片風格**：使用者可在 `job.yaml` 指定 `style` 預設或自訂關鍵字，常見預設包括：
  - `cinematic_realistic`（電影寫實風格）：`"電影感靜幀，35mm鏡頭，膠片顆粒，自然光影，高動態範圍"`
  - `japanese_anime`（日式卡通風格）：`"新海誠日系動漫風格，精緻線條，通透光影，色彩飽和，手繪質感"`
  - `european_fairytale`（歐式童話風格）：`"歐式復古童話繪本，溫暖水彩厚塗，柔和邊緣，奇幻唯美氛圍"`
  - `cyberpunk_neon`（賽博龐克風格）：`"賽博朋克霓虹夜景，雨夜反光，高對比冷暖光，未來科技感"`
  - `retro_scifi`（復古科幻風格）：`"70年代復古科幻插畫，NASA復古海報質感，顆粒雜訊，深邃太空"`
- 要角色／物件跨場像同一個人：把鎖定的參考圖當 `reference_images` 再送給 Gemini（官方 Nano Banana Pro 可多圖；自備 key 節點通常 4 張左右）。第一版可先純文字，角色穩了再加參考圖。
- Gemini 的 seed **不保證**可重現。`--keep-seed` 仍寫進 json 以便記錄，但不要預期跟 SD 一樣同 seed 同圖。不滿意就 `--new-seed` 再抽一張 take，用 `select` 挑。

金鑰放 `pipeline` 的 env（compose `env_file: .env`），**不進 git**。`.env.example` 只留變數名。

### 5.4 安全與配額

- 圖會送到 Google，不適合未授權的真人肖像或敏感內容。
- 安全過濾可能拒圖；被拒時 json 寫 `error`，不覆蓋 current。
- 重產很便宜（相對本機 6GB 出圖），但仍是按張計費。`--count 3` 當預設上限，不要一次抽 20 張。
- 官方 Partner Node 若你之後改用，請當成另一個帳本，不要和 `GEMINI_API_KEY` 混在同一套設定裡。

## 8. 重產 UX（這是核心，不是附加）

原則：**生成是累加 takes，選定才改 current，鎖定才禁止覆蓋。** 不要用 `final.png` 覆寫唯一檔，事後才發現上一張比較好。

### 8.1 CLI（名稱即動作）

在 `pipeline` 容器內：

```text
aivideo parse    --job jobs/20260912_chengshi_yehua
aivideo tts      --job ... [--scene 001_kaichang_yuye] [--new-seed]
aivideo images   --job ... [--scene ...] [--new-seed] [--keep-seed]
aivideo srt      --job ...
aivideo compose  --job ...
aivideo run      --job ...                 # 缺什麼補什麼；跳過 locked

aivideo regen    --job ... --scene 001_kaichang_yuye --only image --new-seed
aivideo regen    --job ... --scene 001_kaichang_yuye --only speech
aivideo regen    --job ... --scene 001 --only image --keep-seed
aivideo regen    --job ... --only compose

aivideo lock     --job ... --scene 001 --image
aivideo lock     --job ... --scene 001 --speech
aivideo unlock   --job ... --scene 001 --image

aivideo select   --job ... --scene 001 --image image_20260912T154402
aivideo preview  --job ...                 # 重產 preview.html
```

`aivideo run` 行為：

1. 讀 `job.yaml` + 各 `scene.yaml` + 檔案是否存在。
2. 沒有 speech 且未 lock → TTS。
3. 沒有 image 且未 lock → 出圖。
4. 語音時長變了 → 重寫 SRT。
5. 成片過期 → compose。
6. 已 lock 且 current 存在 → 跳過並在 log 標 `skipped:locked`。

`regen --only image --new-seed`：

1. 拒絕在未 `--draft` 時覆蓋 locked image。
2. 呼叫 Gemini API（或可選 ComfyUI Gemini 節點），寫新 take 到 `takes/`。
3. 將 `image.png` / `image.json` 指到新 take，更新 `scene.yaml` 的 `current.image_take`。
4. 標記 compose 過期，**不重跑 TTS**。

TTS 批次結束後對 ComfyUI 呼叫 free memory，把 OmniVoice 卸掉。出圖走雲端，不必跟 TTS 搶 GPU。

### 8.2 預覽頁（比開資料夾聽 wav 快）

`preview.html` 每場一列：縮圖、音訊播放、時長、seed、lock 狀態、take 下拉。第一版可以是靜態 HTML（pipeline 生成）；之後才做按鈕打 API。人的工作流：

1. `aivideo run`
2. 開 preview，聽／看
3. 不滿意的場：`regen --scene … --only image|speech --new-seed`
4. 滿意的場：`lock --scene … --image` 與／或 `--speech`
5. 全部鎖定後 `compose`

### 8.3 其他減少重工的作法

- **台詞微調不必重抽圖。** 只 `regen --only speech`。
- **圖只差一點：** 改 `image_prompt` 再產。Gemini seed 不保證同構圖，靠多 take + `select`。
- **一次抽 N 張再選：** `regen --only image --count 3`，寫三個 take，再用 `select`。雲端可並行 1–2 張，預設 N=3，避免配額與費用爆掉。
- **Compose 永遠便宜。** 調字幕位置、字級、zoom 節奏只重跑 FFmpeg。
- **Takes 不自動刪。** 磁碟比重抽便宜。要清用另外的 `aivideo gc --job … --keep 5`。
- **不要在 ComfyUI 視窗裡當正式產線。** 視窗只拿來調通 workflow 範本。正式產物一律走 CLI，否則 seed／prompt 不會進 json，下一輪無法重現。

## 9. 腳本創作與雙模式流程

專案支援兩種創作入口，兼顧「自備文案」與「主題靈感由 AI 搜集資料生成」：

### 9.1 雙模式工作流

#### 模式一：【直接口白模式】（自備文案，直通分鏡）
- **輸入**：使用者直接提供寫好的口白或段落。
- **處理**：
  1. 依 YouTube 觀看節奏（每場約 5～8 秒、1～2 句話）智慧切分成 `## 001`、`## 002`...。
  2. 依劇情與景別交替（遠景、中景、特寫）設計畫面描述與對應的英文 Prompt。
  3. 產出 `script.md`。

#### 模式二：【主題生成與語氣仿寫模式】（審查確認制）
- **輸入**：使用者提供「故事主題」與可選的「參考口白範例」。
- **處理**：
  1. **聯網資料檢索**：運用 Gemini Google Search Grounding 搜集真實背景史實與轉折點。
  2. **語氣仿寫（Tone Persona）**：嚴格模仿使用者提供的語氣範例（句式節奏、口語化用詞、設問句、反轉、情感標籤如 `[sigh]`）。
  3. **初稿確認點**：先產出「純文字故事草稿」，由使用者閱讀、修訂台詞與確認滿意度。
  4. **分鏡切換**：使用者確認後，才切出場次並配上畫面風格 Prompt，正式寫入 `script.md`。

### 9.2 口吻風格庫（範本示例）

- **經典範本：趣味科普與商業奇招風格（米其林模式）**
  - **特徵**：強烈的黃金 8 秒設問開場（「如果你今天要去...你敢相信...居然是...嗎？」）、生動口語化比喻（「沒錯 就是那個白色一圈一圈...」）、反詰質疑後反轉（「這根本是一筆虧本生意啊！對吧？錯了...」）、節奏緊湊。
  - **適用**：科技秘辛、冷知識、商業歷史傳奇（如羅曼太空望遠鏡、阿波羅計畫、歷史奇案）。

### 9.3 畫面風格預設庫（Image Style Presets）

使用者在建立 Job 時可指定畫面風格，會自動轉換為相應的 `style_prefix` 與提示詞工程：

| 風格代號 | 中文名稱 | Prompt 風格前綴（Style Prefix） |
|----------|----------|----------------------------------|
| `cinematic_realistic` | 電影寫實風格 | `電影感靜幀，35mm鏡頭，膠片顆粒，自然電影光影，高動態範圍，精細細節` |
| `japanese_anime` | 日式卡通風格 | `新海誠日系動漫風格，精緻線條，通透唯美光影，色彩飽和，二次元手繪質感` |
| `european_fairytale` | 歐式童話風格 | `歐式古典童話繪本插畫，溫暖水彩厚塗，柔和邊緣，奇幻童趣，精緻筆觸` |
| `retro_scifi` | 復古科幻風格 | `70年代復古科幻太空插畫，NASA復古海報風格，顆粒質質感，深邃星空，機械構造` |
| `cyberpunk_neon` | 賽博龐克風格 | `賽博朋克霓虹夜景，雨夜反光，高對比冷暖色調，未來科技感，細節豐富` |

### 9.4 腳本格式（`script.md`）

`script.md` 用簡單分隔，避免一開始就上複雜 DSL。

````markdown
# 城市夜話

## 001 開場・雨夜巷口
畫面：雨夜窄巷，地面反光，一盞暖色路燈，沒有行人
旁白：雨還在下。巷口那盞燈，像有人故意留著。

## 002 主角獨白・窗邊
畫面：室內窗邊側臉剪影，玻璃上有雨滴，室內只有一盞檯燈
旁白：我本來以為，把窗關上就聽不到外面的聲音。
````

`aivideo parse` 產出對應 `scene.yaml`。已存在且 lock 的場，parse **不覆蓋** `narration` 以外你鎖住的產物；prompt 若腳本改了，只更新 yaml，不自動重產，直到你 `regen`。

一場旁白建議 1–3 句、約 4–12 秒。太長就拆場，重產粒度才小。

## 10. 成片（FFmpeg，不經 ComfyUI）

對每場：

1. 以該場 `speech.wav` 時長為鏡頭長度（可加 0.3–0.5 秒頭尾靜音）。
2. `image.png` 做緩慢 `zoompan`（例如 1.00 → 1.08）。
3. 串成視訊，混上串接後的 `narration.wav`。
4. 字幕：
   - 預設 **hard**：`subtitles=` 燒進畫面（Shorts / 抖音友善）。
   - 可選 soft：MP4 `mov_text` 或另附 `.srt`。
5. 縮放到 1920×1080。編碼：視訊 `h264_nvenc`（2060 支援 NVENC）或 libx264；音訊 AAC。

字幕時間軸由各場 wav 時長累加，不靠 Whisper。只有「外部音訊要轉寫」才需要 Whisper，第一版不做。

字型放 `assets/fonts/`，compose 時複製到 pipeline 容器內 FFmpeg 能讀的路徑。中文字型缺失會變成方框，這是成片檢查項。

## 16. 關鍵決定

1. **雙容器**：pipeline 編排 + compose 裡的 `comfyui` 只跑 TTS，VS Code 只進 pipeline。**不用秋叶整合包當正式後端。**
2. **畫面 16:9**，交付 1920×1080。
3. **出圖用 Gemini**（自備 `GEMINI_API_KEY`）。日常 `gemini-3.1-flash-image` 1K；定稿可升 Pro / 2K。產線預設 pipeline 直連，ComfyUI 節點只供手調。
4. **TTS 用 OmniVoice-bf16 / fp16 / eager**。音色 `narrator_zh_tw`：**先 Voice Design（`女，青年，中音调` + 鎖定 seed），之後同一 id 改克隆**。官方清單沒有台灣腔，真台灣口音靠參考音。
5. **時間軸由語音時長產生 SRT**，FFmpeg 成片。
6. **產物以 take 累加、current 選定、lock 保護**，CLI 按場、按種類重產。
7. **路徑 ASCII、內容中文**；OmniVoice 權重放 932 GB SSD 上的 Linux volume。
8. **GPU 只跑 TTS**；出圖不佔 2060。
